# Agent Note: 产品合约与编译归属覆盖

Status: implemented

## Problem

产品 Host API 缺少文档生成所需的参数和结果合约，产品类型及服务没有子系统归属。一个 Host 装配浏览器测试被 Client 编译排除，却没有加入 Host 编译，真实类型问题因此表现为成片 error-typed lint 诊断。文档发布测试还依赖普通 Windows 用户不具备的文件符号链接权限。

## Decision

产品 API 在源码说明实际持久化、版本、重放和失败行为。[产品参考](../../../../docs/reference/subsystems/man-roleplayer.md)拥有相关身份与 RPC 类型，生成服务表链接到该页。浏览器投影继续由其 Client 包说明，不伪装成 Host 服务。Host Service 将产品品牌 `MessageId` 局部别名为 `ProductMessageId`，让生成链接与核心 LLM 消息身份区分，两种类型本身保持不变。

h26 装配测试加入 Host 编译归属，使用当前单人物开始、随后明确邀请的流程，保留稳定困惑身份与操作归属断言。生成期间人物切换遵循已确认的产品规则，测试不重新引入切换时自动取消。

文档发布 fixture 在 Windows 使用目录 junction，其他平台使用目录符号链接；二者都将图片解析到仓库外，验证同一拒绝行为，无须修改权限设置或跳过断言。

## Alternatives considered

**将产品类型当作通用框架原语。** 产品对话、执行和证据归属与核心类型不同，明确的文档归属能保留这些区别。

**保留旧浏览器选择器与标题位置假设。** 当前产品从单人物开始，表格顺序也不能将记录绑定到本用例；显式邀请和唯一标题保留原有隔离与生命周期断言。

**要求文档发布 fixture 使用提升权限的文件符号链接。** 目录 junction 能在现有 Windows 权限下覆盖同一真实路径越界场景。

## Consequences

编译配置、源码合约、子系统归属与生成目录共同维护，质量检查保留已有规则和断言。上游 CI 引用注明其来源，本产品源码交付不因此声称启用了这些工作流。本地检查不证明真实模型质量、跨平台行为或生产恢复。
