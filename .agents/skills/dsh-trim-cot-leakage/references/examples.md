# 过程叙述识别样例

与 [清理指引](../SKILL.md) 配合使用。先判断文字是否给维护者提供当前义务或耐久理由，不按关键词机械删改。

| 候选 | 处理方式 |
| --- | --- |
| 未提交草稿中的“决策 7”“审计 B3”“设计 §4” | 找到已提交拥有者并换成真实链接；无有效内容则删除 |
| “本 PR 增加”“后一个堆叠 PR 会实现” | 当前文档说明实际机制；未实施内容保留在明确提案中 |
| “以前这样，现在那样” | 当前说明写现有行为，必要原因归决策或复盘 |
| “评审认为”“按审查者要求” | 核对真实技术依据，删掉以评审权威替代原因的句子 |
| 分支、变量、断言的逐步复述 | 若代码已经表达就删除；保留非显然约束 |
| “大概够用”“应该安全” | 提供实际界限或未知范围，不能改写成没有证据的肯定 |
| 已实现记录里仍写迁移计划 | 改为已落地决定及代价，不把尚未实现的部分写成完成 |

以下内容不是应删的过程叙述：事件和清理的必要顺序、所有权、明确测试缺口、有效 issue/RFC 引用、coverage/lint 豁免理由、空 catch 的真实失败范围，以及决策记录里的替代方案。

避免过度纠正：不得把“调用者必须做某事”改为“框架保证做到”；不得把假设变成已发布能力；删掉周围推理后仍应保留真实事实与数据来源。运行时“旧连接排空后启用新连接”描述活动对象，不是仓库历史。
