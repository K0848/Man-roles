# 工程审阅

先确认实际改动、基准和已有工作区状态，只读审查不授权修改或远程操作。用 [根规则](../../../AGENTS.md)、[包规则](../../../packages/AGENTS.md)、[防御模式](../../../docs/development/defensive-patterns.md) 和所属决策理解周边实现，不把旧上游 CI 当作本项目证据。

## 重点

- 跟踪接口的定义、实现和全部受影响消费方，核对配置、错误、取消、所有权和清理时机。
- 注册和回调验证卸载，异步准备在发布前建立 owner，失败路径保留回滚及清理收敛。
- 权限拒绝落到最终执行入口，检查直接或替代调用能否绕过 schema、包装或 listener。
- 公共选择、抽象、缓存、兼容分支和防御措施对应当前需求；无当前消费方不意味着可以直接删除明确契约。
- 观察权威状态和外部结果，不用方法存在、固定示例、模型自述或测试通过总数替代行为证据。
- 用户或模型可见输出核对实际内容与相应快照；源码检查不能证明 Loader、构建 bin、worker 或真实 provider 已走通。
- 文档和 JSDoc 随公共行为更新，类型粘贴、生成内容和链接由所属检查约束；正文只维护一份中文，不要求镜像或 sidecar。

## 报告问题

描述位置、触发条件、影响与证据，先列会改变结果的问题，再列建议；不把风格偏好列成阻塞。范围紧的缺陷附在真实代码行，跨模块问题集中说明。对现有评审逐条核实后修复或解释，不因评论存在就接受结论。

只报告实际执行的检查和未覆盖风险。审查正确性不由 lint、覆盖率或上游流程自动保证；准备提交或推送时按 [定向验证](../dsh-pre-push-checks/SKILL.md) 选择一次充分证据。
