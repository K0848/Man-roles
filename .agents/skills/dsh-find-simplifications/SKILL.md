# 工程精简

先明确目标、授权和影响范围。检索当前生产调用、配置、生成内容、测试及决策，区分运行消费方、验证用途和纯历史。不能只因目录大、代码旧、符号未被静态引用或实现复杂就删除。

## 判断依据

优先寻找重复状态、没有当前消费者的抽象、只保护已退役行为的兼容层，以及有成熟替代但仍承担维护成本的自实现。每个候选说明当前 owner、真实消费、保留理由、净减少量和必要验证。

生命周期复杂度按 owner 与结算点分析；只在多份状态描述同一事实时合并，保留回滚、取消、回调隔离、清理收敛和首次终态等独立约束。类型已保证的同进程调用不伪造恶意输入来支撑防御；配置、持久化、进程及网络入口仍按真实边界验证。

引入依赖只有能减少自有实现、测试和维护时才成立；生产依赖变化仍按授权确认。来源和 vendor 本地修补不能当作无关上游遗留覆盖。

## 决策与实施

不确定或改变产品能力的候选先给具体取舍；范围已明确的实施按最小改动接通上下游。非琐碎决定写 [Agent Note](../../notes/README.md)，记录真实替代方案、代价和未验证项，不补造历史。

同主题旧笔记先判断完全或部分替代，保留独有理由并修复入链；冻结归档不改。删除或移动遵守准确范围授权，不自动增加镜像、sidecar 或归档任务。

按本次实际变化验证，报告源码、运行或交付分别得到什么证据。验证充分就结束，不为凑候选数、测试数或记录数继续扩大工作。
