| # 需求文档（man-roleplayer）                                 |
| ------------------------------------------------------------ |
|                                                              |
| > 项目代号：man-roleplayer（暂定）                           |
| > 一句话定位：**向古人问惑** —— 以 AI 扮演先哲，用其思想与真实事迹回应你当下的困惑。 |
|                                                              |
| ## 一、需求背景                                              |
|                                                              |
| ### 缘起                                                     |
|                                                              |
| 我自己在学习哲学的过程中，积累了不少困惑。除了找真人沟通，我想到另一种方式：让 AI 扮演历史上的先哲（如王阳明、曾国藩等），我把自己当下的情景困惑输入进去，由「他」来为我解答。 |
|                                                              |
| ### 要解决的问题 / 痛点                                      |
|                                                              |
| 1. 困惑需要被回应，但找真人沟通存在局限（时间、隐私、立场、专业性）。 |
| 2. 抽象的哲学概念难以直接「用」到具体处境上 —— 我需要的不只是道理，而是「如果是他，会怎么想、怎么做」。 |
| 3. 一位先哲的视角，往往不足以覆盖一个复杂困惑的不同侧面。    |
|                                                              |
| ### 产品目标                                                 |
|                                                              |
| 做一个「角色扮演式问惑」产品：用户输入当下困惑，AI 以某位先哲的身份、口吻、思想体系、以及他**真实做过的事**来回应，帮助用户在具体处境中获得启发。 |
|                                                              |
| ### 关键设计原则（约束）                                     |
|                                                              |
| - 概括是「有损的指针」：摘要携带要点 + 出处，原文留在可追溯的位置。 |
| - 用户原话与 AI 回答在摘要时**分离**，不做笼统一锅烩。       |
| - 人物 voice 与事迹知识可分离：voice 轻量常驻，事迹库按需加载。 |
| - 宁可牺牲「全自动」，也要保证引文出处正确（先哲伪托语录风险高）。 |
|                                                              |
| ### 技术基座与方向                                           |
|                                                              |
| - 基于 DSH 插件形式开发。                                    |
| - 核心逻辑（树分支引擎、分角色摘要、人物 voice、剧情路线投影）倾向以「替换 Provider」的方式自定义，而非迁就现有插件默认行为；DSH 的会话 / 日志 / 沙箱 / 路由等底座复用现成能力。 |
| - 参考 piagent 的树分支机制作为交互与上下文管理的设计原型（移植其**设计语义**，而非代码）。 |
|                                                              |
| ## 二、需求罗列                                              |
|                                                              |
| 1. **以事证理**：回答必须落到该先哲「真实做过的事」上 —— 生平抉择、真实案例、原话语录，而非只讲抽象思想概念。 |
| 2. **多人物**：支持多位先哲（首批：王阳明、曾国藩），可切换角色。 |
| 3. **树分支对话**：用户与某位先哲的对话是一条分支；困惑与 AI 的解释可以分叉到另一条分支（另一位先哲），形成对话树。 |
| 4. **同 session 连续**：所有人物分支同属一个 session；切换角色不丢失此前各人物的对话与概括。 |
| 5. **分支低污染**：切换分支时，只把「概括层」带过去（而非原文整体灌入）；概括时要把「用户信息」和「AI 信息」分开处理。 |
| 6. **原文可追溯**：有一个管理侧能力知道「原生信息在哪」，需要时可按出处取回原文，而不是只依赖摘要。 |
| 7. **剧情路线面板**：一个实时更新的面板，整理用户的「困惑路线」（问题 A / B / C …），并按人物累积各自的概括。 |
|                                                              |
| ## 三、任务拆解                                              |
|                                                              |
| ### 阶段 0：准备与验证                                       |
|                                                              |
| - **T0.1 环境准备**：确认 DSH 开发环境 / Web GUI 可用、插件可加载。 |
| - **T0.2 机制 spike**：验证「替换 Provider」的 seam 可用，确认「单 session 内 seq 段 = 分支」是否可行。 |
|                                                              |
| ### 阶段 1：人物库内容工程                                   |
|                                                              |
| - **T1.1 王阳明 persona**（身份 / 口吻 / 思想概括）          |
| - **T1.2 王阳明事迹库**（生平大事 / 关键抉择 / 原话 / 案例） |
| - **T1.3 王阳明事迹索引**（一句话 + 关键词 + 出处）          |
| - **T1.4 曾国藩 persona**                                    |
| - **T1.5 曾国藩事迹库**                                      |
| - **T1.6 曾国藩事迹索引**                                    |
|                                                              |
| ### 阶段 2：角色扮演回答                                     |
|                                                              |
| - **T2.1 人物 voice 接入**：以人物口吻 / 思想回应。          |
| - **T2.2 事迹检索**：按话题取 top-k，事迹不进上下文。        |
| - **T2.3 以事证理**：回答引用真实事迹 + 出处。               |
|                                                              |
| ### 阶段 3：树分支与摘要                                     |
|                                                              |
| - **T3.1 人物切换**：切角色。                                |
| - **T3.2 分角色摘要引擎**：用户原话保留 / AI 回答提炼要点。  |
| - **T3.3 原文可追溯**：出处指针 + 取回原文。                 |
| - **T3.4 同 session 多人物连续**。                           |
|                                                              |
| ### 阶段 4：剧情路线面板                                     |
|                                                              |
| - **T4.1 人物切换卡片**（UI）。                              |
| - **T4.2 剧情路线面板**：实时、跨人物累积。                  |
| - **T4.3 面板与摘要 / 原文联动**。                           |
|                                                              |
| ### 阶段 5：集成、验收与打磨                                 |
|                                                              |
| - **T5.1 端到端联调**                                        |
| - **T5.2 验收**                                              |
| - **T5.3 优化**                                              |
|                                                              |
| ### 建议的最小闭环                                           |
|                                                              |
| 先做 **T1.1–T1.3 + T2.1–T2.3**（王阳明一人 + 以事证理），跑通主线；再做 **T3、T4**。 |
